# T6: Sim-to-sim sanity check before hardware deployment

- **Owner:** TODO
- **Status:** in progress (existing work in a Codex session, to be handed off)
- **Depends on:** a trained, exported policy from T2, T3, T4, or T5
- **Repos:** `isaac_ros_deploy` (deployment stack), IsaacLab `junnosuke/mpm_rl_task` (export)
- **Paper target:** none directly. This is the gate every policy passes before the hardware experiments of Q2 to Q5.

## Goal
Before a policy runs on the real G1, confirm in the deployment stack's MuJoCo simulation that the exported policy behaves as it did in IsaacLab. This catches export and interface errors (observation order, joint order, action scale, gains, timing) on a simulator instead of on the robot.

## Starting points
- `~/workspace/isaac_ros_deploy/README.md`: container setup, MuJoCo launch (`hardware_type:=mujoco`), hardware launch, safety blending.
- `~/workspace/isaac_ros_deploy/VALIDATION.md`: what has been validated so far and its stated limits. As of its 2026-10-29 tests, the MuJoCo check was a short zero-command run, not a locomotion-quality test, and no physical G1 test had been run.
- Policy bundles: `ros_ws/src/isaac_ros_robots/unitree_g1/g1_bringup/policies/` (MPM, RFT flat, RFT rough, rigid rough, reduced-order, and NeRD locomotion bundles exist).
- Export side: `scripts` / `isaaclab_rl` export entry points in IsaacLab; exported policies under `~/isaac/IsaacLab/exports/`.

## Steps
1. **Export check.** For each bundle, compare the deployed ONNX output against the IsaacLab policy on recorded observations.
2. **Interface check.** Confirm observation terms, order, history length, scaling, joint order, action scale, PD gains, and control rate match the training task. Record them side by side.
3. **Closed-loop check.** Run each policy in the deployment MuJoCo simulation with a fixed command script (stand, forward, lateral, yaw, stop). Record falls, velocity tracking, and joint torque and velocity against limits.
4. **Compare with IsaacLab.** Run the same command script in IsaacLab on rigid ground and compare tracking and gait timing.
5. **Go / no-go.** Write a short verdict per policy.

## Acceptance criteria
1. Numerical match between deployed and IsaacLab policy outputs, with tolerance stated.
2. Side-by-side interface table for each policy, with any mismatch flagged.
3. Closed-loop results per policy for the fixed command script: fall count, velocity tracking error, peak torque and joint velocity relative to limits.
4. Comparison against the IsaacLab run of the same script.
5. A go / no-go verdict per policy, naming the bundle and the training run it came from.
6. Stated limits: the deployment simulation is rigid-ground MuJoCo, so it checks the policy interface and basic stability, not behavior on granular terrain.
