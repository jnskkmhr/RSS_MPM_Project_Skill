## Goal
Keep the paper consistent with the context repo: every experiment is described as its task file defines it, every claim matches `DECISIONS.md`, and every number comes from `FINAL.md`.

## Inputs
| What the paper states | Source |
|---|---|
| Numbers and measured results | `FINAL.md` only |
| Scope, claims, and what is in or out of the paper | `DECISIONS.md` |
| Experiment descriptions: modes, sweeps, trajectories, metrics and their definitions | `tasks/T1.md` to `tasks/T6.md` |
| Project claim and contributions | `ONBOARD.md` |

Do not take facts or numbers from `outputs/`. Outputs are unchecked until a check passes and the lead merges them into `FINAL.md`.

## Rules
- Edit only the paper repo. Do not edit code repos, task files, `DECISIONS.md`, or `FINAL.md`.
- Every number that is not in `FINAL.md` stays `\pending{}`.
- Figures come from `site/T<n>/fig/` and only for results labelled `checked` there and listed in `FINAL.md`. T7 has no slides of its own.
- If the paper needs something no task produces (a figure, a metric, an experiment), add it under "Proposed tasks" in `tasks/README.md`. Do not write it into the paper as if it existed.
- If a task file or decision contradicts the paper's claim, or cannot support it, report it to the lead instead of rewording around it.
- Follow the paper conventions in `ONBOARD.md`: one sentence per line, result paragraphs start with a bold one-sentence claim tagged with its question, author notes use the macros in `shortcut.tex`.

## Detecting changes
The paper session is not notified when a plan changes. It finds out in two ways:

- **Told.** The lead marks the question `stale` in the "Paper sync" table in `tasks/README.md`, with the reason, and the user or lead says so in the session.
- **Checks for itself.** At the start of every work session, and before any edit to a question's paragraphs, run in the context repo, using the commit recorded for that question in `outputs/T7.md`:

  ```bash
  git -C ~/RSS_27/RSS_MPM_Project_Skill diff <aligned-commit>..HEAD -- tasks/ DECISIONS.md FINAL.md
  git -C ~/RSS_27/RSS_MPM_Project_Skill status --short
  ```

  The diff is exactly what changed since the paper was last aligned. Uncommitted changes shown by `status` are not settled; ask the lead before acting on them.

## Steps
1. **Align.** When the lead marks a question stale in the "Paper sync" table in `tasks/README.md`, re-read that question's task file and `DECISIONS.md` (`git log -p` in the context repo shows what changed) and update the matching paragraphs. Carry scope or claim changes into the abstract, introduction, and methodology where that question is claimed.
2. **Fill.** When a row in `FINAL.md` gains a passing check, replace the matching `\pending{}` with the value, units, and conditions exactly as stated there.
3. **Report.** After each pass, update `outputs/T7.md` and tell the lead, who clears the stale mark.

2. Every number in the paper that is not `\pending{}` traces to a row in `FINAL.md`.
3. Claims in the abstract, introduction, and methodology agree with `DECISIONS.md` and `ONBOARD.md`.
4. The paper builds with `latexmk paper.tex` without errors.
5. `outputs/T7.md` is current: each question's row names the context-repo commit it was aligned to.
