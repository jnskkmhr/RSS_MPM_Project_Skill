## 6. Failed attempts

1. **Passing `free_velocity` (post-rewind velocity) instead of `begin_velocity` into `ParticleNeRDLocalNetwork.step_from_history` during closed-loop coupling (`closed_loop.py`):**
   - Caused a velocity-input mismatch with training (`pre_rigid_step`) during impact frames. Fixed by passing `begin_velocity` to the neural network while keeping `free_velocity` for `RecordedForceEstimator`.
2. **Using `NewtonShapeCfg(mu=0.5)` on static tray walls in `particle_nerd_local` (`box`, `sphere`, `cylinder` tasks):**
   - Because all 1,000 `particle_nerd_local` training trajectories used `shape_material_mu = 1.0`, passing `mu = 0.5` into the collider pair feature (`pairs[..., 7]`) fed an out-of-distribution friction input to `collider_encoder`, causing the entire sand bed (`q_mean_z`) to drift downward by `-106.4 mm` in 100 steps ("viscous clay" collapse). Fixed by setting `default_shape_cfg` `mu = 1.0` and enforcing `mu = 1.0` in `ParticleNeRDLocalSolver.__init__`.
3. **Using two separate `wp.HashGrid` instances (`local_agg` grid and `estimator._batch_grid`) inside a single captured `torch.cuda.CUDAGraph` (`contrib/particle_nerd_local`):**
   - In Warp (`warp/native/hashgrid.cpp` line 329), `hash_grid_update_device_impl` uses a single function-local `static HashGrid_t<Type> grid;` host staging variable for its async `wp_memcpy_h2d` into the device `HashGrid` descriptor. When two different `wp.HashGrid` objects (`local_agg` with `r = 0.072` and `estimator._batch_grid` with `r = 0.065`) called `.build()` inside the same CUDA graph capture, the second `.build()` overwrote the static host staging struct before the captured H2D DMA of the first `.build()` replayed, corrupting `local_agg`'s grid descriptor on replay (`pk_mean` dropped from `1.26` to `0.12` and surface deformation vanished after step 1). Fixed by sharing the same `wp.HashGrid` instance and radius (`0.072 m`) between `local_agg` and `estimator._batch_grid` and replaying the CUDA graph on Warp's stream (`with torch.cuda.stream(wp.stream_to_torch(stream)): graph.replay()`).
4. **Adding a heuristic contact-push gate `w_push` in `ParticleNeRDLocalNetwork.step_from_history`:**
   - Attempted to boost local foot-wake displacement on large 50,400-particle beds, but introduced ad-hoc behavior and pushed sub-body supporting particles during downward impacts. Removed completely so `model.py` uses the exact trained update equation `pos_next = pos_cur + g_inert * (dx_inert + corr) + g_col * dx_col`.
5. **Multiplying `effective_mass_scale` by `rft_packing_mobilities` (`~90.8x`) in `WorldParticleProxyEstimator` (`particle_world/contact.py`):**
   - Turned `effective_mass_scale = 10.0` into `eff_n = 908.4` (`47.6 kg` per particle), preventing `2.0 kg` elementary objects from penetrating the sand surface. Replaced with the standard directional effective-mass formula (`effective_mass_scale`, `horiz_mass_scale`, `up_mass_scale`, `tangent_mass_scale`, `normal_power`) matching `ContactEstimator` and `ProxyEstimator`.
